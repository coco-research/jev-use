The Repo Standard.
Standing instructions.

Every repository you own carries the same skeleton, the same gate, and the same six documents. This is the instruction set. An agent reads this once and can bring any repo into compliance without asking.

0How to use this document

Read this section before the rest. It tells you what to do, in order.

  1. Run the audit first. repo-check --repo <path> reports exactly what is missing. Do not guess.
  2. Fix tier 1 before anything else. Tier 1 is mandatory for every repo, no exceptions, no judgement calls.
  3. Copy, do not invent. Every file in tier 1 has a template in this document. Use it verbatim, then adjust the content.
  4. Re-run the audit. It must say COMPLIANT before you consider the job done.
  5. Never delete a document to make the audit pass. An empty placeholder is worse than a missing file, and the audit treats both as failures. That is deliberate.
The one rule under all the others: a document that lies is worse than no document, because the next agent will act on it. If a change makes a document wrong, fix the document in the same commit.

1The ten standing rules

These are not stylistic. Each one exists because its absence caused a specific, observed failure.

01
Every repo has an AGENTS.md at root, under 160 lines.
It is the one file an agent reads first. Not rules — a map: where the documents are, which one wins when they disagree, what to read first. Five of seven repos were missing it, so every agent started from zero.
02
Work lands through a small PR. Nothing is pushed straight to main.
A PR is where a change becomes explainable. A commit on main is where it becomes anonymous.
03
A gate runs before every push, and it is local.
CI can be refused (a private repo on an exhausted budget was, outright), and a hosted runner cannot test anything that needs a GUI session. The hook cannot be refused and takes 1.5 seconds.
04
Evidence, never assertion, in the PR body.
"Tests pass" is a claim. The command and its real output is a fact. Every PR template section exists to force the second.
05
One owner per fact.
Two documents must never both be authoritative for the same thing. Two sources of truth is a bug that reads as documentation.
06
An invariant is written with the measurement behind it.
"Set the messaging timeout" is an opinion and gets removed. "Without this timeout the call hangs rather than fails; measured on PI-Desktop returning CannotComplete" is a fact and survives review.
07
Dead ends are recorded, not deleted.
The cheapest and most-skipped thing in any repo. One sentence — "we tried X, it failed because Y" — saves the next agent the hour you already spent.
08
No credential reaches a tracked file, a log, or a commit message.
Read secrets by path at runtime. Never copy one in. If one lands, remove it and rotate it — assume it is already public.
09
A public repo carries a LICENSE. No licence means legally untouchable.
Without one, the default is all rights reserved: nobody may legally use or contribute to the code, no matter how public it looks.
10
A tool that cries wolf gets ignored, and then protects nothing.
Two false positives were removed from the audit before it shipped: a PEM header inside a test that verifies keys are withheld, and a placeholder token literally named not-production. A check that fails on correct code teaches you to skip the output.

2What every repo carries

Three tiers. Only tier 1 is mandatory. The structure is identical across repos on purpose: an agent that knows one repo knows all of them.

repo/
├── README.md                what it is, how to run it. 60 lines max.
├── AGENTS.md                  TIER 1. the routing table. under 160 lines.
├── CONTRIBUTING.md          the loop, branch naming, PR size, cadences.
├── LICENSE                  TIER 1. required the moment a repo is public.
├── .githooks/pre-push         TIER 1. the gate. committed, not in .git/hooks.
├── .github/
│   ├── workflows/ci.yml     backstop for anyone who skipped the hook.
│   └── pull_request_template.md  TIER 1. forces evidence over assertion.
├── docs/
│   ├── prd.md               what and why
│   ├── architecture.md      how the parts fit
│   ├── rules.md               the laws, each with its measurement
│   ├── design.md            what it looks like
│   ├── tasks.md             the live board
│   └── memory.md              decisions and dead ends
├── .metagpt/
│   ├── STATE.md             starts with "Next action:". one glance.
│   ├── GATE.json            machine-readable gate state
│   └── interview.md         what was asked and answered, before design
└── src/ or crates/
Why .githooks/ and not .git/hooks/: the latter is never committed. It exists on one machine and dies with the clone. Commit the hooks, then git config core.hooksPath .githooks once per clone.

AGENTS.md — the routing table

The one file an agent reads first. Keep it under 160 lines. It is a map, not an essay — detail belongs in docs/.

# AGENTS.md — read this before touching anything

## 0. The documents, and when each is authoritative

| File | Answers | Update when |
| --- | --- | --- |
| `docs/prd.md` | What and why | Scope changes |
| `docs/architecture.md` | How the parts fit | Structure changes |
| `docs/rules.md` | The laws. Invariants | ONLY with owner approval |
| `docs/design.md` | What it looks and feels like | UI work |
| `docs/tasks.md` | What is worked on now | Every PR |
| `docs/memory.md` | Decisions and dead ends | Every PR that settles something |

If two documents disagree, the earlier one in that table wins. Never
silently pick one — fix the disagreement in the same PR.

## 1. The PR contract

- Every change is a small PR. No direct pushes to `main`.
- Gate green before review. Run `.githooks/pre-push` or `git push` and let it.
- Evidence, not assertions. Paste the command and its real output.
- One concern per PR. Two things touched means two PRs.
- Fill the PR template in honestly, including the Risk section.

## 2. Never commit

- Any API key, token, or secret. Not in code, not in docs, not in a fixture.
- Absolute personal paths in shipped code. Docs may name one as an example.
- Build output. `target/`, `dist/`, `node_modules/` are ignored and stay ignored.

## 3. When unsure

`docs/rules.md` holds the invariants, each with the measurement that justifies it.
If a task appears to require breaking one, stop and ask.

## 4. Recording what you learned

`docs/memory.md` is not a diary. It records decisions with reasons and
dead ends worth not repeating. If you spent an hour proving a
hypothesis wrong, that sentence saves the next agent the hour.
.githooks/pre-push — the gate

Adapt the middle to the stack. The shape does not change: fast checks first, secrets last, refuse loudly.

#!/usr/bin/env bash
# The gate. CI is a backstop; this is what actually holds.
# Install once per clone:  git config core.hooksPath .githooks
# Bypass only in a real emergency:  git push --no-verify  (and say why in the PR)

set -uo pipefail

fail() { printf '\nGATE BLOCKED  %s\n' "$1" >&2; exit 1; }
step() { printf '  ... %s\n' "$1"; }
ok()   { printf '  ok  %s\n' "$1"; }

# 1. Formatting — cheapest, so it runs first
step "format check"
cargo fmt --all -- --check >/dev/null 2>&1 || fail "run: cargo fmt --all"
ok "fmt"

# 2. Lints, with the same flags CI uses
step "lint"
out=$(cargo clippy --workspace --all-targets -- -D warnings 2>&1) || {
  printf '%s\n' "$out" | tail -30 >&2; fail "clippy found problems"; }
ok "clippy"

# 3. Tests
step "test"
out=$(cargo test --workspace 2>&1) || {
  printf '%s\n' "$out" | tail -40 >&2; fail "tests failed"; }
n=$(printf '%s\n' "$out" | grep -oE '[0-9]+ passed' | awk '{s+=$1} END {print s+0}')
ok "test (${n} passed)"

# 4. Refuse a credential before it reaches the remote
step "credential scan"
pats='sk-[A-Za-z0-9]{20,}|gho_[A-Za-z0-9]{20,}|gcli_[A-Za-z0-9]{10,}'
hits=$(git diff --cached -U0 --diff-filter=ACMR | grep -E '^\+' | grep -Eo "$pats" | head -5 || true)
[ -n "$hits" ] && { printf '%s\n' "$hits" >&2; fail "a credential is staged"; }
ok "no credentials staged"

printf '\nGATE PASSED\n'
Python, JS, Go: swap steps 1-3 for the local equivalents (ruff format --check + ruff check + pytest, or prettier --check + eslint + npm test). Keep the order. Keep the credential scan last.

docs/rules.md — the invariants

The highest-value file in any repo, and the one nobody writes. Each rule carries the measurement that justifies it, or it is just an opinion and will be removed by the next person who finds it inconvenient.

# Rules

The invariants. These do not change without the owner's explicit approval.

Every rule here has a measurement behind it. They are not stylistic
preferences; each exists because breaking it caused a real, observed failure.

Any PR that changes a rule in this file must say so in its title.

---

## R1 — <the rule, as an instruction>

Enforced by: <the code that makes it true>

Measured: <the number, and how it was obtained>

Why it matters: <what breaks when this is violated, in concrete terms>

---

## R2 — ...
Worked example from a real repo: R2 — the messaging timeout is mandatory, and it is set before the walk. Enforced by Limits::messaging_timeout_secs, default 2.0. Measured: you cannot cancel a blocked AX attribute read. Why it matters: that timeout is the only thing stopping one unresponsive app from pinning a worker forever. Observed: PI-Desktop reproducibly returns CannotComplete on every attribute while other apps answer normally. Without the timeout the call does not fail — it hangs.

That survives review because you cannot argue with it.

4The four cadences

Four different memory lengths. Skipping a short one is cheap. Skipping a long one is how a repo rots.

1
Every commit — 0 s, automated
The gate. If it is not automated it will be skipped. 1.5 seconds warm is the budget; if yours is slower, fix that before adding checks.
2
Every PR — 60 s, by hand
Update tasks.md. Update memory.md if a decision was made or a dead end hit. That is the entire difference between a PR and a commit on main.
3
Weekly — 5 min, in tasks.md only
Move done to Done with the PR number. Re-rank. Delete anything that has been "next" for three weeks. That last one matters more than the others.
4
Monthly — 20 min, read the rules against the code
Is every invariant in rules.md still enforced by a test? Prune memory.md of anything now obvious. Check architecture.md still describes the real tree.

5How to verify — repo-check

A standard nobody can verify is a suggestion. This is the mechanical audit, and it is what an agent should run before claiming a repo is compliant.

# audit the repo you are standing in
repo-check

# audit another
repo-check --repo ~/code/thing

# machine-readable, for CI or an agent to parse
repo-check --json

# only the mandatory tier
repo-check --tier 1

exit 0 = compliant. exit 1 = gaps. exit 2 = the check itself broke.

What it checks

TierChecksFails the audit?
1 REQUIREDREADME, AGENTS.md (and its length), LICENSE, .githooks/pre-push, core.hooksPath wired, no credentials in product codeYes
2 EXPECTEDCI workflow, PR template, CONTRIBUTING, docs/rules.md, tests, machine-specific paths flaggedNo — reported
3 DOCUMENTSThe six docs plus .metagpt/STATE.md and GATE.json, checked for stubs and placeholdersNo — reported
What it deliberately does not do: fail you for a "TODO" in a draft, or for absolute paths in a private repo's logs. Both were in the first version and both were removed, because a check that fires on legitimate work is a check you learn to ignore.

7Applying it — the exact sequence

Cheapest first. Do not do all of this in one afternoon; documents written as an exercise are stale within a week.

1
Wire the gate in every repo
Copy .githooks/pre-push, run chmod +x, then git config core.hooksPath .githooks. One file, one command, per repo. This is tier 1 and it takes two minutes each.
2
Add AGENTS.md to the four repos missing it
Under 160 lines. A map, not rules. Copy the template above and fill the table with where that repo's documents actually live.
3
Add a LICENSE to coco-hermes
Match whatever the parent repo uses. Without one the code is legally untouchable.
4
Write docs/rules.md for the repo you touch most
Ten bullets, each with a measurement. Not six repos — one. Watch whether it changes a review before rolling it out. This is the highest-leverage document and you have none.
5
Add the PR template and start memory.md
Only after step 4 proved itself. The template is a copy; memory takes real writing.
The thing to resist: creating all six documents in all six repos because the audit says so. An audit is a map of the gap, not a work order. Fix the gate everywhere, then earn the rest repo by repo.

If you remember one thing

Maintenance is not tidying. It is keeping the memory the next session depends on. A human forgets and asks. An agent forgets and guesses — confidently, in your repo, at three in the morning. These six documents and one shell script are the difference between an agent that continues your work and one that re-derives it badly.
