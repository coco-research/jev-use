2The test that tells you whether a document should exist

Not "is it nice to have". This one question:

Delete it. What breaks?
If nothing breaks, it does not belong. If the next session wastes an hour, it belongs and it is missing.
prd.md
what & why
The problem, the non-goals, the phases, the measured constraints.
Breaks without it: scope. Someone builds group D before group A.
rules.md
the laws
Invariants, each with the measurement behind it. Not style preferences.
Breaks without it: an agent removes a timeout because it "looks unnecessary", and the process hangs.
memory.md
decisions & dead ends
Chosen, why, rejected, why. Plus: what did not work.
Breaks without it: the same wrong hypothesis gets tested again next week.
tasks.md
what is in flight
Now, next, blocked, done. With PR numbers.
Breaks without it: "what were we doing?" is answered by reading code.
architecture.md
how it fits
The layers and the boundary between them.
Breaks without it: new code lands in the wrong layer.
design.md
what it looks like
Tokens, spacing, states, and what is banned.
Breaks without it: the UI is different on every pass.
AGENTS.md is not in the list above because it is not a document, it is a routing table. It says where the other six live and which wins when they disagree. Keep it under 100 lines.

3Four cadences. Most repos have one, and it is the wrong one.

Each is a different length of memory. Skipping a short one is cheap; skipping a long one is how a repo rots.

1
Every commit — 0 seconds, enforced by a hook
The gate. fmt, lint, test, secret scan. If it is not automated it will be skipped. ~/code/jev-use/.githooks/pre-push is the pattern: 1.5 s, installed once.
2
Every PR — 60 seconds, by hand
Update tasks.md and, if a decision was made, memory.md. This is the entire reason PRs exist rather than commits on main: a PR is where a change becomes explainable.
3
Weekly — 5 minutes, in tasks.md only
Move done to Done with the PR number. Re-rank. Delete anything that has been "next" for three weeks. That last one matters more than the others.
4
Monthly — 20 minutes, read the rules against the code
Is every invariant in rules.md still enforced by a test? Prune memory.md of anything now obvious. Check architecture.md still matches find . -name '*.rs'.

4The structure. Same for every repo.

repo/
├── README.md            what it is, how to run it. 60 lines max.
├── AGENTS.md            the routing table. where everything lives.
├── CONTRIBUTING.md      the loop, branch naming, PR size, cadences.
├── LICENSE
├── .githooks/           COMMITTED hooks. core.hooksPath points here.
│   └── pre-push
├── .github/
│   ├── workflows/ci.yml
│   └── pull_request_template.md
├── docs/
│   ├── prd.md             what & why
│   ├── architecture.md      how it fits
│   ├── rules.md            the laws + the measurement behind each
│   ├── design.md           UI, tokens, banned patterns
│   ├── tasks.md            the live board
│   └── memory.md           decisions and dead ends
├── .metagpt/
│   ├── STATE.md         starts with "Next action:". machine-and-human readable.
│   ├── GATE.json        gate state per stage. one glance, no reading.
│   └── interview.md     what was asked and answered, before design
├── reference/           pointers to what this was ported from. NOT vendored.
└── src or crates/
Why .githooks/ and not .git/hooks/: the latter is never committed, so it exists on one machine and dies with the clone. Commit the hooks and set core.hooksPath once.

5Five rules that make a repo work for agents, not just people

Your repos are read by agents more often than by humans now. That changes what "well maintained" means.

  • A stale doc is worse than a missing one. A missing doc costs a question. A stale one gets acted on. A PR that makes a doc wrong must fix it in the same PR.
  • Evidence, not assertion. "Tests pass" is a claim. The command and its output is a fact. Every PR template section exists to force the second.
  • One owner per fact. Two documents must never both be authoritative for the same thing. The table in AGENTS.md says which wins.
  • Small PRs, because context is finite. A 400-line diff cannot be reviewed by an agent holding 12 other things. A PR should be reviewable in two minutes.
  • Record the dead end. The cheapest and most-skipped thing in any repo. One sentence saves the next agent an hour. ~/.pi/agent/AGENTS.md got five commands moved from line 286 to line 7 for exactly this reason.

If you remember one thing

Maintenance is not tidying. It is keeping the memory the next session depends on. A human forgets and asks. An agent forgets and guesses — confidently, and in your repo. The six documents are not bureaucracy; they are the difference between an agent that continues your work and one that re-derives it badly.
