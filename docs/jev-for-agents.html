Jev is a selection model.
Not a chatbot.

Given a numbered list of things on screen and a goal, it returns one operation and one element index in about 400 ms. Code executes it. It does not plan, explain, or remember. Everything below is measured on this machine.

1The five commands

CommandUse it for
jev-use "goal" --app <App>Drive any macOS app: click, type, menus, dialogs
jev-browse <url> "goal"Drive a browser page — the web content itself
jev-use --table --app <App>Print the element table. No model call. Free.
jev-use --appsList apps that have a UI
jev-checkAudit that everything works

2The mistake that costs the most time

Chrome is two programs in one window. jev-use can reach one of them.

JEV-USE Chrome's own controls

Toolbar, menus, address bar. All reachable.

  • New tab, Back, Reload, Bookmark
  • The URL bar — it is a real text field
  • Every menu: File, Edit, History
$ jev-use "open a new tab" \
    --app "Google Chrome"
JEV-BROWSE The page inside

Invisible to the accessibility tree. Measured: 1246 nodes walked, 17 usable, and zero page text.

  • Links, forms, search results
  • Anything you would call "using the website"
$ jev-browse https://news.ycombinator.com \
    "open the top story"

3Look before you drive

--table costs nothing and answers "can Jev even see this app" in under a second. Always start here.

$ jev-use --table --app Terminal

Terminal — rijulkalra — -zsh — 80×24  (465ms, 20 addressable of 878 nodes)
  [1] radiobutton    ~ — -zsh ="True" [x]
  [2] button         Close tab
  [3] button         new tab
  [4] button         Button
20 of 878. The rest were rejected — hidden, disabled, or off screen. That filtering is the point: an element you can see but cannot use must never become a target.

4Most "status" questions are not GUI tasks

This is in the guide because reaching for automation first is 20× slower than reading the data directly.

TaskRight toolTime
"Status of project X?"read its database / git status~50 ms
"What did I work on yesterday?"query stored timestamps~50 ms
"Uncommitted work in repo Y?"git -C <repo> status --porcelain~50 ms
"Open app Z"open -a "<App>"instant
"Open a URL"open <url>instant
"Click Settings in app Z"jev-use0.5–2 s
"Search for X on site Y"jev-browse~400 ms/step

5Measured limits — so nothing over-promises

ThingReality
One Jev decision250–900 ms
One desktop step, end to end0.5–2 s
A 5-step task5–15 s
A structured query~50 ms
Browser page per step~400 ms
Desktop is not as fast as browser. The guide says this explicitly, because promising browser speed for desktop work is the easiest way to look broken.

What does not work

  • Chromium apps with accessibility off expose almost nothing. PI-Desktop exposes 229 elements; a Chromium app with a11y disabled returns a near-empty tree.
  • An app with no open window exposes only its menu bar. Correct behaviour, not a bug.
  • Very deep trees truncate at 2000 nodes / depth 25.
  • Secure input fields block synthetic keystrokes.

6Hard rules in the guide

1
Playwright is banned on this machine
Not for screenshots, not for driving a page, not as a fallback. Includes agent-browser and plugin_pi_browser_*. Why it matters: a Playwright fullPage screenshot once injected 920 KB of image into a 750 K-token context and broke a session for an hour.
2
Never modify cocoteams, jev-ultrafast, or OpenMAIC
cocoteams is AGPL-3.0, reference-only, frozen — work there cannot cross the licence into cocoteams-ng. The other two are not ours.
3
Astra needs a human yes, every time
gpt-6-astra is expensive, review-only. Never a default, never a fallback.
4
A sub-0.70 confidence decision is a guess
Say so rather than acting on it.

8One thing found while installing this

All 15 files in ~/.grok/rules/ are broken symlinks. They point at ~/coco-research/rules/cursor-mdc/, which does not exist. So are 182 of the 183 skills.

Grok does not read that directory for rules — it scans for Agents.md, AGENTS.md, AGENT.md, Claude.md — so this is not breaking anything today. But 197 dead links is worth knowing, and it is exactly why the new files went in as real files rather than symlinks.
